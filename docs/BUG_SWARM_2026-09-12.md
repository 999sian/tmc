## Confirmed shutdown defect

[Audio/TTS exit crash #184](https://github.com/999sian/tmc/issues/184) is closed
on GitHub, but both normal quit paths in `port/port_bios.c` call `exit(0)`.
This bypassed the audio and TTS shutdown calls after `AgbMain()` in
`port/port_main.c`. The SDL callback could race destruction of audio backend
statics, and TTS's joinable worker could terminate the process when its static
state was destroyed.

The fix registers each subsystem's idempotent shutdown with `atexit` after
initialization. This also covers prelaunch exits for TTS. The handlers run
before pre-main C++ static destructors; the subsequently registered RA
shutdown runs before audio, then TTS. Failed audio initialization is safe to
shut down again. Audio mix and command scratch vectors now initialize before
`main` as well: leaving them as function-local statics would let their later
registered destructors free callback buffers before the shutdown handler.

The parent run reproduced SIGSEGV (process return -11) before the fix, after
capturing frame 30 with audio enabled. Local evidence:
`/tmp/tmc-swarm-smoke-g7t_6p_l/exit-before.log` and the accompanying
`bugreport_20260912_214258` directory. The same audio-enabled frame-30 exit
returned zero after adding the shutdown handlers. Final staged-binary results
are recorded below.

For before/after verification, build with `xmake build -y tmc_pc`. Create a
fresh temporary working directory for each run, link `assets` to
`dist/USA/assets` and `sounds.json` to the staged file, then run the absolute
`build/pc/tmc_pc` path with:

```sh
TMC_BASEROM=/home/sian/Documents/tmc/build/pc/baserom.gba \
TMC_AUTOPLAY=1 SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy \
TMC_CAPTURE_FRAME=30 TMC_CAPTURE_OUT=/tmp/tmc-exit-after.png \
/home/sian/Documents/tmc/build/pc/tmc_pc
```

Do not pass `--no-audio`: the callback must be active. Check that the log
reaches `Port layer initialized. Entering AgbMain...`, frame capture succeeds,
and the process exits zero without a crash report. Keep the fresh temporary
directory so normal user configuration and saves are untouched. This is an
exit-path regression check, not a gameplay completion test.

## Independently reproduced defects

- **Config numeric overflow and frame stalls:** loading `window_scale: 1e100`
  triggers an undefined float-to-integer conversion in the original loader.
  Large unsigned values can wrap into valid settings, and a tiny positive
  `practice_slowmo` can overflow the frame-period conversion or stall the game.
  Numeric ranges are now checked before conversion, colors clamped before
  conversion, and loaded practice speed restricted to the setter's 0.05–1.0
  range. The production-loader regression fails against the baseline and
  passes with UBSan including float-cast-overflow checks.
- **Sprite JSON out-of-bounds write:** an object key equal to `ULONG_MAX`
  wraps the original `maxIndex + 1` allocation size to zero before writing
  the vector. Keys now require complete decimal parsing and an index below
  the engine's 512-entry capacity; array input is bounded too. The production
  parser regression covers malformed keys, boundary indices, oversized arrays,
  and valid entries with ASan/UBSan.
- **Audio buffer destruction race:** a tracked-allocation regression verifies
  audio scratch buffers remain alive until the shutdown handler stops audio.
  The original function-local declarations fail this ordering check.
